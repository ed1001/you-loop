# Étude 0.3.0 — release prep design

**Date:** 2026-07-03
**Type:** Release preparation (marketing + website + store assets). No product-code behavior changes.

## Purpose

Étude is already published (Chrome Web Store + AMO, currently 0.2.5). Since the
store copy, website, and screenshots were written, two headline features shipped
and the saved-loops model grew. The public surfaces are now behind the product.
This release brings website copy, store listings, launch copy, and store
screenshots up to date for a **0.3.0** update, and fixes one store-review
accuracy bug.

The in-app `features/player-overlay/HelpModal.tsx` is the source of truth for
current feature vocabulary; all public copy should agree with it.

## The gap (what's undocumented publicly)

1. **Pitch shift** — transpose the song without changing tempo. Hold the pitch
   readout and drag to shift in semitones (±12); hold **Shift** to zoom the dial
   into cents for fine-tuning, release to zoom back out. Fling right to snap back
   to 0 st.
2. **Count-in** — a metronome counts you in before the loop starts. Tap or drag
   the tempo, pick the time signature and how many bars. An on-timeline beacon
   marks the count.
3. **Saved loops enrichment** — a saved loop now snapshots the loop region, zoom,
   **and** count-in; a pencil control renames a loop or replaces it with the
   current one; last-used loop re-applies on the next visit.
4. **Sync accuracy bug** — the site and `store-listing.md` already describe
   browser-account sync, but `cws-review-answers.md` still says the `storage`
   permission has "no sync." This contradiction must be reconciled (honest store
   review), see §4.

## Scope

In scope: `site/`, `docs/marketing/**`, `package.json` version, submission
checklist. Out of scope: any change to extension runtime code, `CONTEXT.md`
domain glossary, and actually publishing/pushing (stops at a reviewable diff +
regenerated assets, per the repo push gate).

## 1. Store screenshots — full redesign (5 shots)

**Constraint:** Chrome Web Store allows a maximum of **5** screenshots
(1280×800). AMO allows more. Target set is **5**, which fits Chrome exactly and
is used verbatim on AMO.

**Method (unchanged, proven):** `scripts/generate-screenshots.mjs` renders the
**real** extension UI — the production `PAGE_UI_STYLES` string pulled verbatim
from `entrypoints/content/pageUi.styles.ts` plus markup mirroring the real
`.you-loop-*` class names — transform-scaled on a flat `#0f0f10` étude-brand
canvas with an instructional caption + brand stamp, captured by headless Chrome.
Template CSS in `docs/marketing/screenshots/templates/shot.css`.

**"Full redesign" intent:** keep the proven DNA (real UI, dark canvas, teal
accent `#2dd4bf`-family, Fraunces caption + Instrument Sans body, brand stamp,
"Free · No account · No tracking" tag). Elevate for consistency and add the two
new features. This is a considered elevation, not a reinvention that regresses
the shots that already read well.

Redesign moves applied across all shots:
- One unified caption/eyebrow system and consistent hero-control placement
  (centered, lit, never cut off).
- **Refresh the stale `pill()` fragment** so the control pill includes the
  **pitch readout pill** (`you-loop-pitch` / `you-loop-pitch-value` /
  `you-loop-pitch-num` / `you-loop-pitch-st`) and the **count-in toggle glyph**
  (`you-loop-countin-toggle`), matching the real current panel. Every current
  shot renders the old pill, so all four are stale regardless.

## 4. Store-review accuracy (`docs/marketing/`)

Reconcile the storage/sync language so both reviewer docs are truthful and
consistent with the site + listing:

- **`cws-review-answers.md`** — the `storage` justification currently reads
  "No remote storage, no sync, no network use." Rewrite to: saved loops persist
  locally via `storage`; if the user has the browser's own account sync enabled
  (Chrome/Firefox), loops ride that built-in, browser-handled sync the same way
  bookmarks do; **Étude runs no server, makes no network requests, and collects
  no data.** Keep the host-permission and remote-code answers as-is.
- **`amo-reviewer-notes.md`** — same reconciliation in the Permissions section;
  bump the version referenced in build output paths to 0.3.0.

The `storage` manifest permission is unchanged; only the *description* was
inaccurate. `browser_specific_settings.gecko.data_collection_permissions.required
= ["none"]` remains correct (no data is collected by Étude).
